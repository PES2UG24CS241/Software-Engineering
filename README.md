# Bank Management System

A console-based Bank Management System developed in C++ as part of our Software Engineering mini-project at PES University.

The project demonstrates basic banking operations, input validation, customer authentication, and persistent file-based storage.

## Features

### Sprint 1 — Core Banking Functionality

- **Account Creation:** Create a customer account with a generated account number.
- **Customer Login:** Authenticate using an account number and four-digit PIN.
- **PIN Masking:** Mask PIN characters during entry in the console.
- **Deposit Money:** Deposit positive amounts into an account.
- **Withdraw Money:** Withdraw money while preventing withdrawals that exceed the available balance.
- **Balance Inquiry:** View account details and the current balance.
- **Input Validation:** Handle invalid menu choices, non-numeric amounts, and zero or negative transaction amounts.
- **Persistent Account Storage:** Save account details and balances locally so they remain available after restarting the application.
- **Transaction History:** Record deposits and withdrawals with timestamps, transaction amounts, and resulting balances.

*Transaction history is being integrated and must be verified before this feature is considered complete.*

## Technology Stack

- **Language:** C++

- **Development Environment:** Dev-C++

## Prerequisites

- A C++ compiler such as GCC or TDM-GCC.
- A terminal or C++ IDE such as Dev-C++.
- Windows is recommended for the current implementation because PIN masking uses `<conio.h>` and `_getch()`.

## How to Run

1. Clone or download this repository.
2. Open `main.cpp` in Dev-C++ or another compatible C++ IDE.
3. Compile the source code.
4. Run the generated executable.
5. Create a test account and use the account number and PIN to log in.

Alternatively, with a compatible GCC installation on Windows:

```bash
g++ main.cpp -o bank.exe
bank.exe
```

## Data Storage

The application uses local text files:

- `accounts.txt` — stores customer account information and balances.
- `transactions.txt` — stores transaction records, including timestamps and balances after transactions.
- `temp.txt` — temporary file used when updating account records.

These files are generated by the application at runtime. Do not commit real customer data or generated test data to the repository.

## Testing

The following Sprint 1 scenarios should be verified:

- Account creation and login.
- Successful deposits and withdrawals.
- Rejection of zero and negative transaction amounts.
- Rejection of withdrawals when funds are insufficient.
- Correct balance inquiry.
- Account balance persistence after restarting.
- Transaction history persistence after restarting.

## Limitations

This is an academic project intended to demonstrate software engineering principles. It is not production-ready banking software. In particular, PINs are stored in the current text-file implementation without secure password hashing, and file-based storage is not designed for concurrent or production banking transactions.
